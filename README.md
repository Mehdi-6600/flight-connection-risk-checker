# بررسی ریسک کانکشن پرواز

ابزار داخلی، فارسی و راست‌به‌چپ برای کمک به کارشناس فروش بلیت در ارزیابی اولیهٔ اتصال دو پرواز. محاسبه کاملاً در مرورگر انجام می‌شود؛ API، هوش مصنوعی، پایگاه‌داده، حساب کاربری یا سرویس پولی لازم ندارد.

> این ابزار برآورد داخلی ارائه می‌کند و امکان انجام ترانزیت را تضمین نمی‌کند. MCT رسمی، قوانین لحظه‌ای ایرلاین/فرودگاه یا مقررات مهاجرتی از این برنامه دریافت نمی‌شود.

## قابلیت‌ها

- فرم دو پرواز با فرودگاه، ایرلاین، شماره پرواز، تاریخ و ساعت محلی هر فرودگاه.
- پیش‌نمایش زندهٔ اتصال (کد فرودگاه، زمان اتصال و ساعت حرکت) پیش از ارسال فرم.
- فهرست سبک فرودگاه‌های رایج با کدهای IATA/ICAO، نام فارسی/انگلیسی، شهر، کشور، منطقهٔ زمانی IANA و فرودگاه‌های هم‌شهر.
- تشخیص یکسان‌بودن فرودگاه، تغییر فرودگاه در یک شهر (برای نمونه IST ↔ SAW)، اختلاف شهر، عبور از نیمه‌شب و اتصال روز بعد.
- محاسبهٔ زمان واقعی اتصال با درنظرگرفتن منطقهٔ زمانی و DST.
- شرایط اتصال به‌صورت chips قابل‌کلیک (نوع بلیت، نوع انتقال، بار، پذیرش مجدد، Immigration، ترمینال، تغییر فرودگاه، امنیت) با حالت پیش‌فرض «نامشخص».
- امتیاز deterministic از ۰ تا ۱۰۰، چهار سطح رنگی، عامل‌های امتیاز، توضیح انسانی و توصیهٔ داخلی.
- تخمین محافظه‌کارانهٔ زمان لازم برای اتصال؛ به‌وضوح با برچسب «برآورد داخلی، نه MCT رسمی».
- شبیه‌سازی تأخیرهای ۱۵، ۳۰، ۴۵، ۶۰، ۹۰ و ۱۲۰ دقیقه با همان موتور ریسک.
- کپی نتیجه، چاپ مرورگر/ذخیره به PDF، کارت‌های مسیر پرتکرار برای پرکردن سریع، تاریخچهٔ محلی با شمارنده و حذف رکوردها.
- حالت روشن/تاریک دستی با ذخیرهٔ انتخاب در همان مرورگر (پیش‌فرض: تنظیم سیستم).
- رابط موبایل‌محور، دسترس‌پذیر، RTL و PWA قابل نصب؛ محاسبه پس از بازدید اول به‌صورت آفلاین نیز در دسترس است.
- `noindex` در صفحه، `robots.txt` و هدرهای عدم ایندکس برای استفادهٔ داخلی.

## پیش‌نیاز و اجرا

- Node.js نسخهٔ ۲۰ یا جدیدتر
- هیچ dependency اجرایی یا توسعه‌ای لازم نیست.

```bash
npm install
npm run dev
```

سرور توسعه روی `0.0.0.0:4173` اجرا می‌شود. برای ساخت و بررسی خروجی Production:

```bash
npm test
npm run build
npm run preview
```

پیش‌نمایش خروجی ساخته‌شده روی پورت `4174` بالا می‌آید. سرورهای توسعه/پیش‌نمایش فقط برای اجرا و آزمون محلی‌اند؛ Vercel فایل‌های ثابت `dist/` را سرو می‌کند.

## ساختار پروژه

```text
index.html                     پوستهٔ فارسی و RTL
src/main.js                    فرم، اعتبارسنجی، نتیجه، تاریخچه، Copy/Print و PWA
src/styles.css                 طراحی responsive و استایل چاپ
data/airports.js               فهرست فرودگاه‌ها و مناطق زمانی
data/README.md                  وضعیت dataset و منبع عمومی برای به‌روزرسانی
data/common-routes.js          مسیرهای صرفاً نمونه برای ورود سریع
src/lib/airports.js             جست‌وجو و تشخیص کد/شهر فرودگاه
src/lib/connection-questions.js تعریف chips شرایط اتصال و مقدارهای مجاز
src/lib/time.js                 اعتبارسنجی تاریخ/ساعت و تبدیل IANA به UTC
src/lib/risk-engine/engine.js   منطق مستقل و قابل آزمون امتیازدهی
src/lib/risk-engine/risk-rules.js وزن‌ها، آستانه‌ها و قواعد قابل تنظیم
public/                         manifest، service worker، آیکون و robots.txt
scripts/                        ساخت static و سرورهای بدون dependency
tests/                          تست‌های واحد، قرارداد DOM و جریان یکپارچهٔ فرم تا تحلیل
tests/helpers/dom-stub.mjs      DOM بسیار کوچک برای اجرای src/main.js در Node
test-data/scenarios.json        سناریوهای نمونهٔ غیرواقعی/فرضی
docs/risk-model.md              تعریف فرمول و محدودیت‌های مدل
```

## موتور ریسک

امتیاز پایه و وزن‌ها در `src/lib/risk-engine/risk-rules.js` قرار دارند؛ منطق مستقل UI در `src/lib/risk-engine/engine.js` است. همهٔ مقادیر در بازهٔ ۰ تا ۱۰۰ محدود می‌شوند. محدودهٔ سطح‌ها و فرمول MCT داخلی در [`docs/risk-model.md`](docs/risk-model.md) شرح داده شده است.

تاریخ/ساعت ورودی، ساعت محلی فرودگاه انتخاب‌شده محسوب می‌شود. اتصال بر اساس timestamp واقعی UTC محاسبه می‌شود؛ ساعت‌های محلی ناموجود در تغییر DST رد می‌شوند و ساعت‌های تکراری برای بازبینی علامت می‌خورند.

## داده‌ها و محدودیت‌ها

فهرست فرودگاه‌ها یک seed سبک برای مسیرهای پرتکرار است، نه پایگاه جامع یا منبع وضعیت زنده. قبل از استفادهٔ عملی، کد، نام، منطقهٔ زمانی، ساعات فعالیت، ترمینال و شرایط همان itinerary را با منبع رسمی ایرلاین/فرودگاه تطبیق دهید. اگر دادهٔ تأییدشده یا مجوز مناسب برای گسترش فهرست اضافه می‌شود، منبع و مجوز آن باید در همین مستندات ثبت شود.

اطلاعات مشتری در فرم جمع‌آوری نمی‌شود. تاریخچه و انتخابِ تم فقط در `localStorage` همان مرورگر می‌مانند و تاریخچه شامل جزئیات itinerary واردشده است؛ روی دستگاه مشترک یا عمومی از ذخیرهٔ تاریخچه استفاده نکنید و بعد از کار آن را پاک کنید. احراز هویت/کنترل دسترسی سازمانی در این MVP وجود ندارد؛ برنامه را به‌عنوان سامانهٔ محرمانه یا منبع رسمی به کار نبرید.

## آزمون

```bash
npm test
```

تست‌ها با `node:test` داخلی Node اجرا می‌شوند و وابستگی اضافه ندارند. پوشش شامل دسته‌های ریسک، تغییر فرودگاه، Self-transfer، بلیت جداگانه، بار، Immigration، ترمینال، امنیت، تأخیر، DST، جریان یکپارچهٔ دادهٔ فرم تا تحلیل و اتصال رابط کاربری است.

`tests/ui-wiring.test.mjs` دو لایه را بررسی می‌کند: قرارداد استاتیک (هر شناسه‌ای که `src/main.js` صدا می‌زند باید در `index.html` باشد) و اجرای واقعی `src/main.js` روی یک DOM بسیار کوچک داخل مخزن (`tests/helpers/dom-stub.mjs`) برای اطمینان از اینکه فرم، نتیجه، تاریخچه و پیام‌های خطا واقعاً به المان‌های صفحه وصل‌اند. سناریوهای نمونه در `test-data/scenarios.json` فرضی‌اند و دادهٔ پرواز واقعی یا پیشنهاد امن محسوب نمی‌شوند. برای اجرای مرورگر headless، dependency یا مرورگر جداگانه‌ای به پروژه اضافه نشده است.

## استقرار روی Vercel

پیکربندی `vercel.json` از پیش برای build استاتیک آماده شده است:

- Build command: `npm run build`
- Output directory: `dist`
- Environment variables: لازم نیست
- درخواست API یا backend: وجود ندارد

برای انتشار، repository را در حساب Vercel مجاز خود Import کنید و GitHub integration را فعال نگه دارید تا push به branch انتخاب‌شده deployment بسازد. تا زمان اتصال واقعی حساب و اجرای deploy از پنل Vercel، آدرس production یا اتصال خودکار تأییدشده‌ای وجود ندارد؛ این repository به‌تنهایی deployment نمی‌سازد. دامنهٔ رایگان `.vercel.app` فقط پس از ایجاد واقعی پروژه در Vercel صادر می‌شود؛ دامنه‌ای رزرو یا خریداری نشده است.

Workflow گیت‌هاب در `.github/workflows/ci.yml` روی push/PR تست و build را اجرا می‌کند. برای فعال‌شدن آن، branch این پروژه باید به GitHub push شده باشد.

## امنیت و حریم خصوصی

- هیچ secret، کلید API یا ENV لازم نیست.
- دادهٔ فرم به شبکه ارسال نمی‌شود؛ تنها ذخیرهٔ اختیاری، تاریخچهٔ itinerary و ترجیح تم در LocalStorage همان دستگاه است.
- دادهٔ کاربر در UI با `textContent` درج می‌شود و URL شامل دادهٔ پرواز نیست.
- CSP و headerهای پایهٔ امنیتی در سرور نمونه و تنظیم Vercel تعریف شده‌اند؛ صفحه و robots برای noindex تنظیم شده‌اند.
- برای ابزار سازمانیِ قابل استفاده از بیرون، احراز هویت و کنترل دسترسی مناسب را در لایهٔ استقرار اضافه کنید.
